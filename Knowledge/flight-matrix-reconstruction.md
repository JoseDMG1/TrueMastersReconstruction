# Flight profiles and awake evade actions

This continuation applies the REA skill to the retained original ARM64/metadata, corrected local Capstone listings and original Unity data. There is no connected REA MCP or installed rea CLI in this session. All native observations are local-tool evidence. The original gameplay owners/prefab parameters are preserved; new code is opt-in development-player validation.

## Coverage model

`Tools/build-flight-matrix.mjs` derives `FlightMatrixProfiles.json` and `Evidence/flight-matrix-inventory.json` from the twelve-fighter dependency closure plus authored `CreateAwakeAtk` clip events. The inventory contains33 prefabs with enabled Follow and13 additional MoveLight profiles, and five awake evade routes: Raven roll/JumpR/JumpL and Maya JumpL/JumpR.

The matrix instantiates each authored prefab using its real resource and runs normal Unity Start/Update/FixedUpdate, using both fighter ownership layers. It controls two actor roots in a Sora-versus-Amon scene. These are component/prefab production fixtures rather than real normal-attack input routes or every character's collider/state combinations. Four cases per profile/side cover lateral movement, target elevation7, projectile edge positions near radius33, and a synthetic enemy AirAtk collider overlapped with the owner to trigger actual DamageOnCollision dispatch. The collision callback/damage method itself is never invoked directly.

Of the33 statically enabled Follow profiles,32 have a live root Follow in this fixture. FlowerBeam's enabled Follow belongs to FastWaterAtk inside two inactive ancestors (FastWaterAtk and Beam). This fixture preserves that authored dormancy and explicitly checks it; it does not manufacture a flying FlowerBeam or count those eight cases as live steering acceptance. This agrees with the previously observed natural Maya UpAttack visual/damage split.

Hold fixtures synchronize Transform/Rigidbody positions, make actors kinematic, suspend locomotion and root motion, and restore those settings on completion. The long matrix temporarily extends the runtime round timer to3600 and restores its original value; preferences are not changed. Case-created scene roots are removed between profiles. Actor health/Animator/collider state is explicitly reset between component cases. There is no natural AI/knockback/match-flow acceptance in this matrix.

Follow's planar raw cross-dot threshold and turn rate are checked per actual Update. GoForward and MoveWater weakness descent use deltaTime; MoveLight, MoveAttack and MoveRock use fixed-tick displacement. The target starts moving when the authored launch delay elapses, avoiding a test entirely inside a charge animation. Legitimate delayed MoveWater owner-rotation reset is composed with Follow's turn; either native Update ordering is allowed. Inactive projectiles and stop-state transition frames are distinguished from active movement. Pure MoveLight heading is checked after the authored launch/StartRotation window, preserving its original once-only aim.

Follow presence does not imply that all translation continuously homes. RocksJump's MoveRock captures a direction; MoveAttack can move along the local right axis; other attacks have delayed/curved paths. Contacts and target damage are recorded as outcomes, without requiring every fixture geometry or airborne shot to hit. A hit is attributed only when projectile contact and an actual target damage event correlate by frame.

The interrupt fixture records the projectile's actual membership in AttacksManager at the hit. Native DamageOnCollision.DropAllAtks marks registered own attacks; unregistered attacks are not required to acquire playerWeak. Some lightning prefabs retain disabled GoForward or Follow components alongside active MoveLight. Presence alone must not be used to forecast an Update: the observer checks isActiveAndEnabled and stops sampling inactive objects. The old024100 matrix's48 failures included these observer assumptions, delayed owner-yaw reset, and stop-transition frames; it is diagnostic history rather than accepted evidence of combat defects.

## Awake controls

`AwakeJumps` starts each of five routes in a fresh scene, charges/activates the real Special UI, waits for active awakening and recovery, then sends the authored evade UI callback with directional InputReader values. It requires real state entry, the expected object creation, active awakening and recovery. Prefab Awake offsets, such as Raven Shark's1m ChangeStartPosition, are included in spawn-position expectations.

Raven's routes create ShadowSharkAtk, ShadowWolfAtk and ShadowBirdAtk; their live Follow target/yaw and collision outcomes are sampled. Maya's two routes create flowerBonfire, whose root is an area/trap rather than a flying projectile. The moving target must not drag that trap along. No artificial homing was added to it. Charge is accelerated and the CPU movement fixture is explicit; natural charging, close-range suppression/cooldown boundaries and every awakened normal direction are separate gaps.
