## Source-derived input/route contract

MobileInputs quantizes joystick values at strict >.3/<-.3; exact.3 remains0. It writes Horizontal/Vertical and smoothed SHorizontal/SVertical. GameController.Attacking sets Attack only with gameStarted; Jumping sets Jump. AttackingButton assigns the same0/1 to all five attack integer parameters and sets Attack. AnimatorStatesManager.ChangeAtk toggles these integers together and updates A/X presentation. In this implementation these integers select the two directional attack variants; do not conflate X with the separate S/Special button. GameController.Special requires visible SpecialButton, charged SpecialAtk, not decharging, MainCharacter and !Stunned, then sets Special trigger and Stunnedtrue.

Each controller includes the Movement->Attacks route on Attack and Movement->Evade on Jump. Attack/evade selection uses AnimatorTransition entry conditions, not just AnimatorStateTransition edges. Diagonal input can satisfy multiple ordered entries; tests should isolate cardinal directions before exploring ordering. Special trigger plus NumSpecials0 enters Awakening, while NumSpecials1 enters Special. Parent is validating the separate SpecialAtk charge/decharge producer; this worker did not edit SpecialAtk or StatsController.

Acceptance should drive real UI input owners after countdown, wait for Movement and cooldown readiness between attacks, assert actual Animator state and required projectile creation/layer/events, then release buttons. A forced Animator.Play only tests a clip, not entry readiness. Block can be probed using AnimatorStatesManager.Block owner (synthetic trigger declared as such); separately exercise neutral+defense through real controls.
