# Battle presentation reconstruction

Scope: offline helpers in the editable UnityProject. Original recovered exports remain immutable. Backups of replaced working scripts: Evidence/WorkingBackups/battle-presentation-original. This is newly written readable C#, inferred from mapped ARM64 and metadata, not recovered original source. Unity compilation/runtime checks are owned by the root workflow and remain pending for this revision.

## Evidence and retrieval

RAG corpus was rebuilt and queried with CameraManager Counter StatsController AIToggle; retrieved assembly-csharp-symbols.md (CameraManager and BattleSceneSingleton) and native-apk-scenes.md battle component provenance. Retrieval selects candidate evidence; native disassembly and metadata/generic-usage resolutions establish implementation details. Evidence/native-disassembly-{CameraManager,Counter,AIToggle,StatsController,BattleUIManager,ExitMenu,RateGame,LerpManager,FinishMenu}.txt and nested coroutine disassemblies retain exact addresses. Tools/disassemble-type.ps1 correctly translates ELF virtual addresses to mapped file offsets. Cpp2IL's inline disassembly has incorrect image offsets and unsupported control flow and is used only for named call hints. Tools/resolve-native-usage.cjs resolves Cam, GO!, RateGame, A/B, crystal names and tags. Tools/resolve-native-generic.cjs resolves Image/TMP_Text/Toggle/AI generic component lookups. Numeric UI constants are recorded in Evidence/battle-presentation-native-constants.json.

- StatsController: singleton startup, names, health bar reduction, crystal state/flash, local-multiplayer health projection, delayed full restore, five healing passes with particles, attack-icon state, shield bar consumption/recharge, and offline crystal counts. ## Explicit reconstruction correction and pending checks

CameraManager/<ChangeCameraSmooth>d__21.MoveNext at0x128104C adds deltaTime to elapsedTime only on initial state (write0x12810B0); resume state1 jumps0x12810B8, reloads elapsedTime at0x12810C4, and re-enters interpolation/yield without increment. The only other elapsedTime write resets at0x128122C after completion. No original Update method exists on CameraManager. Source-derived inference: duration exceeding the initial delta would keep this native coroutine yielding indefinitely while repeatedly approaching the target. This has not been reproduced in original Android runtime.

The reconstruction deliberately advances elapsedTime on every interpolation frame, then snaps target and resets elapsedTime. This is a design correction, not claimed recovered behavior. Root runtime validation must assert close/far/winner/scene transitions finish by duration plus frame tolerance, target local pose matches, and coroutine does not remain active. Also verify Counter animation invokes the real UnityEvent once, AI starts only afterward, health crystal boundary states1/5/10, shield consumption/recharge, popup opening/closing with serialized curves, and scene reload singleton cleanup. Static source inspection does not establish these runtime outcomes.
